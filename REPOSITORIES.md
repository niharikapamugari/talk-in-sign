# GitHub repository layout

Use three repositories:

| Repository | Purpose | Deploy from |
| --- | --- | --- |
| `talk-in-sign-frontend` | React/Vite user interface | `frontend` |
| `talk-in-sign-backend` | Spring Boot API | `backend` |
| `talk-in-sign` | Project overview, deployment notes, and links to the two source repositories | root |

## Important media note

The downloaded BridgeConn sign videos are intentionally ignored by Git. There are more than 3,000 MP4 files, so they are not suitable for an ordinary GitHub repository. The sign manifest remains tracked.

For deployment, place the clips in object storage/CDN (for example Cloudflare R2, AWS S3, or Supabase Storage), then point the manifest/video URLs to that public asset location. Preserve the BridgeConn attribution and CC BY-SA 4.0 licensing requirements.

## Recommended GitHub setup

1. Create the three empty repositories above on GitHub, with no README, license, or `.gitignore` generated by GitHub.
2. Push `frontend` to `talk-in-sign-frontend` and `backend` to `talk-in-sign-backend`.
3. Keep the root `talk-in-sign` repository as the project hub. Add the frontend and backend repositories to its README as links, or use Git submodules after both remote repositories exist.

Using submodules is optional. Linked repositories are easier for a first deployment; submodules are useful later if you want the root repository to pin exact frontend/backend versions.
